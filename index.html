EU AI Act SDK

A JavaScript library for working with the EU AI Act: the risk classifier the fall-euaiact page runs (prohibited, high, limited or minimal, with the articles that apply), the obligations and the dates they apply from as amended by Regulation (EU) 2026/1744, sealed assessments anyone can check, an Article 12 audit log with a hash chain, Annex IV technical documentation in six languages, an Article 50 disclosure badge, and Ed25519 signing with the platform's own cryptography.

It is the fall-euaiact page's own code, taken out so a developer, or an AI agent, can call it directly. The classifier is a keyword heuristic grounded in the Regulation: a documented starting point, not a legal judgment.

Start here

  1. Install it from GitHub (it is not on the npm registry): 
    npm install github:sjgant80-hub/fall-euaiact-sdk
  2. Import what you need and call it:
    import { classifyText, obligationsFor, assess, verifyAssessment, createAuditShim } from '@ai-native-solutions/fall-euaiact-sdk';

const r = classifyText('An AI system that screens CVs for a recruitment agency.');
// { tier: 'high', articles: ['Annex III(4)'], confidencePct: 60, ... }
obligationsFor(r.tier).deadline;           // '2027-12-02'
const sealed = assess('An AI system that screens CVs…', { at: '2026-11-17' });
verifyAssessment(sealed).valid;            // true, and false if anything in it is changed
const log = createAuditShim();             // IndexedDB in a browser, memory in Node
  3. Or use it in a browser page with no install: 
    import * as sdk from 'https://sjgant80-hub.github.io/fall-euaiact-sdk/src/index.js';
  4. Pin a commit for production (npm install github:sjgant80-hub/fall-euaiact-sdk#<commit>) so what you tested is what runs.

How it works

  1. src/kernel.js is a byte copy of the fall-euaiact repository's kernel.mjs: the classifier the live page runs, proven by that repository's tests and mutation gate. classify() is a thin adapter over it. The product's own gate fails if its sdk/kernel.js differs from kernel.mjs, and this repository's parity check fails if src/ differs from the product's sdk/ by a single byte.
  2. The classifier runs the Article 5 prohibitions first, then the Annex III high-risk uses, then the Article 50 transparency cases; the first tier with a match wins, so a prohibited use is never softened to high. No match is minimal. Confidence is 40 plus 20 per matching trigger, capped at 95.
  3. The dates are Article 113 as amended by Regulation (EU) 2026/1744: Article 5 since 2 February 2025; Article 50 from 2 August 2026; high-risk for Annex III systems from 2 December 2027 and for AI in Annex I products from 2 August 2028.
  4. A sealed assessment hashes the exact text, the tier and the articles together; change any of them and verification fails.
  5. The audit log chains each entry to the previous one by SHA-256. In a browser it uses IndexedDB; the chain check ignores the key IndexedDB writes into each record (before this repair it did not, so every non-empty browser log reported itself as tampered).

For a company that builds, buys or deploys AI in the EU: a first, explainable view of where each system sits under the AI Act, with the dates that apply, and the record-keeping and disclosure pieces you need, inside your own tools.

No dependencies and nothing fetched at runtime (signing used to load a library from a CDN; it now uses the platform's own cryptography). The only outbound call is deepClassify, and only if you call it with your own key.

Compliance and legal

Every verdict names its articles and can be sealed, so a classification on file can be shown not to have been changed later.

Product and engineering teams

An Article 50 badge to drop into a chatbot, an Article 12 log to wire into inference, and an Annex IV draft to start from.

What it costs, against what you pay now

No licence fee and nothing metered. Against an AI-governance platform charged per seat or per system, this covers the first classification, the dates, sealing, logging, disclosure and documentation drafts. It does not replace counsel on a borderline system or a notified body where one is required.

Security and data protection

Everything runs locally except deepClassify, which sends the description you pass to the provider you name, using the key you supply; keys are never stored. The audit log stays in the browser's IndexedDB or in memory. Signatures use WebCrypto Ed25519, matching the RFC 8032 test vector.

Compliance

A heuristic starting point under Regulation (EU) 2024/1689 as amended by Regulation (EU) 2026/1744, not a legal judgment. Dates were checked against the Council's announcement of the Omnibus (EUR-Lex blocks automated checks).

Deployment and roll-out

  1. Install from GitHub and pin a commit.
  2. Classify each AI system in your register with classifyText and seal the result with assess.
  3. Wire createAuditShim into your inference path, and createTransparencyBadge into anything that talks to users.
  4. Run npm run parity before each upgrade, and take borderline systems to counsel.

Risks, answered straight

  • The classifier matches phrases. A system described in unusual words can be missed; the November 2026 repair widened two Article 5 rules (emotion recognition at work or in education, live facial recognition by police in public) after both were found slipping through.
  • Real-time remote biometric identification by police in public is classified prohibited; retrospective identification is high-risk instead, and the verdict says so.
  • deepClassify's OpenAI and Google default models are older and may be retired: pass model for those providers.
  • Annex IV output is a starting draft; the badge text meets Article 50's aim but you decide where and when it is shown.

The explainer

This package used to hold a broken copy of the fall-euaiact page; its main file did not parse. The product repository already had a real SDK folder, but with its own second copy of the classifier, outside the mutation gate, which had drifted from the page. The repair made one classifier: the gated kernel, copied byte for byte, with both repositories refusing any difference.

Testing every module properly found three real faults. Two Article 5 bans slipped through on everyday phrasing. The audit log's chain check failed on every browser log, because IndexedDB writes its own key into each record. And signing loaded its cryptography from a CDN at runtime, which also never worked in Node. All three are fixed in the product and here.

The same pass updated the deep classifier's Anthropic default from a retired model to claude-opus-5-5, and made the article search accept anything without throwing.
